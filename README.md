# 경쟁사 연수 모니터 (하이브리드)

GitHub 저장소 하나로 **매일 자동 수집 → 결과 저장(`data/courses.json`) → 대시보드 자동 표시**까지 끝납니다.
서버도, 구글 서비스계정도, 로컬 PC도 필요 없습니다. 세팅은 아래 순서대로 클릭만 하면 됩니다.

세팅이 끝나면 평소엔 **아무것도 안 하셔도** 됩니다. GitHub가 매일 아침 알아서 수집·저장하고,
대시보드 주소로 들어가면 최신 상태가 보입니다.

---

## 미리 알아둘 것 (1분)
- **GitHub**: 코드를 올려두는 무료 저장소 + 자동 실행(Actions) + 웹페이지 공개(Pages)를 다 제공합니다.
- 이 폴더의 파일들을 GitHub에 올리면:
  - `.github/workflows/monitor.yml` → **매일 08:00(한국시간)** 자동으로 수집 실행
  - `scraper/` → 4개 연수원(티처빌·아이스크림·한국교원·사제동행)에서 신규/종료를 잡아냄
  - `data/courses.json` → 수집 결과가 쌓이는 데이터 파일(기존 2,974건이 이미 들어 있음)
  - `index.html` → 그 데이터를 읽어서 보여주는 대시보드

---

## STEP 1. GitHub 저장소 만들기
1. https://github.com 로그인 (계정 없으면 Sign up으로 무료 가입)
2. 오른쪽 위 **`+` → New repository** 클릭
3. **Repository name**에 `edutech-radar` 입력
4. **Public** 선택 (Pages 무료 공개를 위해. ※ 공개 주소가 됨 — 아래 '주의' 참고)
5. 나머지는 그대로 두고 **Create repository** 클릭

## STEP 2. 파일 올리기
1. 방금 만든 저장소 화면에서 **Add file → Upload files** 클릭
2. 드린 `edutech-radar` 폴더의 압축을 풀고, **안에 있는 항목 전부**(`index.html`, `data`, `scraper`, `.github`, `README.md`)를
   업로드 창으로 **드래그&드롭** (폴더째 끌어놓으면 하위 폴더도 같이 올라갑니다)
3. 아래 **Commit changes**(초록 버튼) 클릭
   - `.github` 폴더가 안 보이면: 파일 목록에 `.github/workflows/monitor.yml` 경로가 포함됐는지 확인하세요. 폴더째 드래그하면 됩니다.

## STEP 3. 자동 실행(Actions) 켜고 첫 실행
1. 상단 **Actions** 탭 클릭
2. "Workflows aren't being run..." 안내가 나오면 **I understand my workflows, enable them** 클릭
3. 왼쪽에서 **monitor** 워크플로 클릭 → 오른쪽 **Run workflow ▾ → Run workflow**(초록 버튼) 클릭
4. 잠시 뒤 실행이 뜨고, 클릭해서 들어가면 로그가 보입니다. **초록 체크(✓)** 면 성공.
   - 로그의 `Run scraper` 단계를 펼치면 `[티처빌] 수집 N / 신규 N` 처럼 사이트별 건수가 찍힙니다.
   - 어떤 사이트가 **수집 0건**으로 나오면 그 사이트만 선택자 조정이 필요합니다(저에게 알려주세요).

## STEP 4. 대시보드 공개(Pages)
1. 상단 **Settings** 탭 → 왼쪽 메뉴 **Pages**
2. **Build and deployment → Source**를 **Deploy from a branch**로
3. **Branch**를 **main** / 폴더 **/(root)** 선택 후 **Save**
4. 1~2분 뒤 상단에 **"Your site is live at https://<아이디>.github.io/edutech-radar/"** 주소가 나옵니다.
   그 주소가 팀과 공유할 대시보드입니다. (즐겨찾기 해두세요.)

## STEP 5. 매일 자동 실행 — 확인만
- 이미 **매일 08:00(KST)** 자동 실행되도록 예약돼 있습니다. 따로 켤 것 없습니다.
- 잘 도는지 가끔 **Actions** 탭에서 초록 체크만 확인하면 됩니다.
- 새 과정이 잡히면 `data/courses.json`이 자동 갱신되고, 대시보드도 자동으로 반영됩니다.

---

## 평소 사용법
- **보기**: STEP 4의 Pages 주소 접속. 좌측에서 `연수 목록` / `경쟁사 분석 보고서` 전환, 상단에서 검색·정렬·상태 필터.
- **엑셀로 옮기기**: 각 행의 **복사** 버튼(그 과정 한 줄) 또는 상단 **표시 항목 복사**(현재 필터된 전체) →
  엑셀에 붙여넣으면 열이 자동으로 나뉩니다.

## 나중에 할 수 있는 것
- **종료 자동정리 켜기**: `scraper/run.py` 위쪽 `FULL_CATALOG_SITES = []` 를
  예: `['사제동행','한국교원']` 로 바꾸면, 매 실행 때 목록에서 사라진 과정을 2회 연속 확인 후 '종료'로 표시합니다.
  단, 그 사이트를 **매번 전체 목록으로 긁고 있을 때만** 켜세요(아니면 오판). 판단이 서지 않으면 그대로 두면 됩니다.
- **티처빌·아이스크림 정확도**: 이 두 곳은 화면을 실제 브라우저로 렌더링해 긁습니다(엔드포인트 불필요).
  첫 실행 로그에서 수집 건수가 이상하면 알려주세요 — 선택자만 조정하면 됩니다.
- **강사명**: 목록에 없어 현재 '미확인'입니다. 필요하면 상세 페이지 파싱 추가로 채울 수 있습니다.

## 주의 (한 가지)
- GitHub Pages 무료 플랜은 **주소를 아는 사람은 접근 가능한 공개 페이지**입니다. 담아둔 내용은 경쟁사의
  공개된 과정 정보이지만, 사내 접근 제한이 꼭 필요하면 말씀해 주세요 — 구글 로그인으로 막는
  Apps Script 방식으로 화면만 바꿀 수 있습니다(수집 엔진은 그대로).
- 각 사이트 `robots.txt`·이용약관을 한 번 확인하고, 하루 1회 저빈도 실행을 권장합니다(현재 설정이 그렇습니다).

## 폴더 구조
```
edutech-radar/
├─ index.html                    대시보드(데이터를 읽어 표시)
├─ data/courses.json             수집 결과(기존 2,974건 시드 포함)
├─ scraper/
│  ├─ run.py                     매일 실행: 수집→신규추가→종료대조→저장
│  ├─ requirements.txt           playwright
│  ├─ config.py, models.py
│  └─ scrapers/                  사이트별 수집 규칙(선택자)
└─ .github/workflows/monitor.yml 매일 08:00 자동 실행
```
